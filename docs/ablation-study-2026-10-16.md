## Baseline

首先不改生产代码，检查环境并运行全套检查；现有项目依赖可用，无需重新安装。
环境为 Linux x64、Python 3.13.5、Node 20.19.2。

核心路径：FastAPI lifespan → monitoring bootstrap → lifecycle 工作线程内 Session →
scheduler → 供应商 adapter → 内存最新价 → 规则计算与数据库告警状态 → Telegram。
最新价/错误是内存状态，轮询失败保留最后成功价格；规则状态、告警与投递结果持久化。
前端路径为 API client → Zod 校验 → 加载状态 hook → React 页面；仪表盘每 120 秒刷新。

## Recommended First Experiment

假设：删除 Binance `_payload_result` 后，行为应保持不变，因为它仅将
`payload.get(price_key)`、identity、metadata path 和 clock 传给 `_price_result`。
后者仍统一负责 Decimal 解析、结果构造与时间戳，不复制其逻辑。

最小修改：两处调用直接取原字段并调用 `_price_result`，删除包装方法。
保留市场选择、mark 优先、mark 缺失后 ticker fallback、异常捕获位置及元数据文本。
E1 没有伴随 rename、整文件格式化、第二项消融或补偿性修改。

预先设定的接受标准：全套检查通过；矩阵输出与副作用一致；HTTP 契约与公开签名不变；
三个局部路径的中位耗时退化各不超过 10%；净减少代码或认知复杂度。
若失败则仅恢复该因素，不扩大修改。

## 输出、接口与副作用对比

在修改前用临时 characterization 脚本记录 144 组输入，修改后运行同一脚本：
3 种市场 × 12 种 mark payload/异常 × 4 种 ticker payload/异常。
其中 96 组覆盖 USD-M/COIN-M，48 组覆盖不支持市场的异常行为。

- mark 包含缺失、null、正常字符串、零、Decimal、float、bool、NaN 字符串、非法字符串、
  timeout、429 类异常和一般供应商异常；ticker 包含正常、缺失、非法价格、timeout。
- 比较完整 dataclass 字段（价格、timestamp、identity、错误类型、message、metadata），
  或向外传播的异常类型/文本，以及客户端路由、调用参数、次数、顺序和时钟调用。
- 144 组均与原始版本及修改前记录一致。正常价格、fallback、错误路径的独立期望
  由现有 `test_adapters.py` 等测试覆盖；全套集成测试覆盖其调度/API 消费者。
- 在仅驻留内存的对照模块中故意将 mark 字段改错，对比器成功检出差异；未写入生产文件。
- `__all__` 中公开对象的构造签名一致（去除 repr 的进程地址），公开方法签名没有修改。
- 排序 JSON 的 OpenAPI SHA-256 前后一致：
  `7ab403203f94c0c9fde678bc1f0bda619ac3919b5012592e64aa2bbc74f984be`。
- API 契约、前端 Zod schema、Python/npm 依赖及 npm 锁文件的 SHA-256 一致。
  前端构建输出文件名和大小也一致。最终 `git diff --check` 通过。

## 配对性能测量

原版通过 `git show` 从固定基线载入独立内存模块，消融版读取工作区，不切换 checkout。
注入固定 Binance 客户端和时钟，计时公开 `get_latest_price`，包括价格解析或异常转译；
每次清空客户端调用记录以避免无限增长。没有真实网络请求。

## 续轮方法与接受边界

续轮开始重新检查环境，后端 225、前端 85 个测试、Ruff、Vulture 和前端构建通过。
没有修改测试以迁就被删除的导出。对已有可导入的命名函数/重导出采用保守兼容标准：
删除若改变模块导入接口，即使页面/调度运行正常，也不纳入本次行为等价精简。
这比只保护 HTTP API 更严格；内部导出不一定是对外承诺，但本轮不擅自迁移该接口。
E4–E6 不代表“存在已证实的生产故障”或“永远不能删除”，而是未满足此次接口保留标准。
失败项在契约检查失败后短路，不继续 benchmark 或修改调用方/测试来制造通过结果。

### E2：删除重复的分母非正检查——接受

假设：有限正数经过 `support < price < resistance` 检查后，两个不同的正有限浮点值
相减得到正分母，不需要再次检查 `denominator <= 0`。仅删除这个三行分支，保留局部变量、
数值解析、非法值检查和区间判断，不合并其他计算步骤。

修改前/后运行同一临时 Node 脚本，用项目 TypeScript 转译器分别加载 Git 原版与工作区版。
24 个字符串值的三重笛卡尔积共 13,824 组，以 `Object.is` 比较结果，覆盖空白、非法输入、
NaN/Infinity、零/负数、最小次正规数、相邻浮点值、普通区间和接近最大有限数。
独立期望包含 `(100, 90, 120) → 2`、`(1e-323, 5e-324, 1.5e-323) → 1`。
另在内存中将 support 边界从 `<=` 错改为 `<`（并去掉冗余保护），对比器成功检出差异。
矩阵输出全部一致；前端 85 个测试（含组件 DOM 测试）、类型检查与构建通过。
源码净减 3 行，该模块 TypeScript AST `if` 数从 10 降至 9，导出签名不变。
没有外观、交互或呈现规则变更，不需要新增视觉设计或截图。

局部微基准轮换正常、边界、次正规数、非法值四组输入；每版预热 100,000 次，
9 轮交替顺序，每轮每版 500,000 次，累加返回值避免丢弃输出。
中位耗时为 0.084466 → 0.082520 μs（−2.30%），满足 10% 退化门槛，不宣称显著提速。

### E3：内联 Hyperliquid scope helper——接受

假设：`_hyperliquid_mids_scope` 只有一个调用点，DEX 和 metadata path 可在适配器中
按相同分支构造，避免返回/拆解中间 tuple 和一次函数跳转。仅内联该函数，不改 symbol
规范化、异常捕获位置、客户端惰性初始化或重试恢复逻辑。

8 种 symbol × 4 种价格/异常共 32 组，比较完整结果、metadata、DEX 调用和时钟调用。
覆盖普通币、大小写/空白、带 DEX 前缀、空串、空前缀、空币名、多个冒号、缺失价格、
非法价格和 timeout。独立检查 `XYZ:crcl` 的 metadata 为 `all_mids.xyz.xyz:CRCL`；
内存中故意删除 path 的 DEX 部分，对比器成功检出差异。
修改前后结果一致；后端 225 个测试、Ruff、Vulture 通过，保留惰性初始化恢复测试。
净减 3 行、1 个函数；Python `if` 数不变，公开对象构造和方法接口不变。

配对微基准计时完整 `HyperliquidAdapter.get_latest_price`，使用固定客户端与时钟，
symbol 为带空白/大小写的 DEX 合约。每版预热 1,000 次，9 轮交替顺序，
每轮每版 50,000 次，客户端调用列表每次清空。
中位耗时 2.735156 → 2.687159 μs（−1.75%），满足门槛。
原版虽然包含 E1 之前的 Binance 实现，但该测量路径完全不调用 Binance，隔离 E3 因素。

### E4：删除默认市场 helper——拒绝并恢复

假设：表单 provider 切换直接取 `marketTypesForProvider(...)[0]!`，可删除默认值包装。
最小实验仅删除 helper、移除表单导入并替换那一处调用，临时净减 5 行。
运行原前端全套测试：84 通过、1 失败；原函数契约测试报
`defaultMarketTypeForProvider is not a function`。构建在 TypeScript 阶段报 TS2724：缺少导出。
页面的 provider/市场类型 DOM 测试仍通过，所以这不是页面行为不等价的证据，
而是模块导入不兼容的证据。未迁移测试或保留新的兼容 wrapper，逐项恢复原修改。
恢复后两个文件与 Git 原版无 diff，85 个测试及构建重新通过；未计时失败版。

### E5：删除 scheduler 命名时钟——拒绝并恢复

假设：将默认时钟改为 `lambda: datetime.now(UTC)` 可删除单调用 `utc_now`，临时净减 4 行。
原有 225 个后端测试、Ruff、Vulture 全部通过；直接检查默认时区和注入时钟均符合原行为。
但修改前成功的 `from wavemonitor_backend.monitoring import utc_now`，修改后报 ImportError。
没有发现仓库内其他生产调用方，不能声称已有外部消费者受损；该探针只证明可导入名称被删。
结合仅节省 4 行、每个 scheduler 新建 lambda 且失去语义名称，按保守接口/可读性标准拒绝。
恢复后文件与 Git 原版无 diff，原导入和 UTC 检查通过，最终全套后端检查通过。
未计时失败版，不以测试通过代替接口兼容判断。

### E6：删除 serializer 重导出——拒绝并恢复

假设：生产 create/update 直接导入 serializer，因此可删除 API client 的单行重导出。
只删该行，未改 serializer、生产调用或测试导入。
前端原测试 84 通过、1 失败，报 `serializeInstrumentLevelsForApi is not a function`；
TypeScript 构建报 TS2459：模块只在本地声明，没有导出。失败原因明确为模块导入接口改变。
这里不是删除了未使用实现：重导出有一个实际测试消费者。节省一行不足以抵消兼容变更，
因此恢复该行，保留原测试。恢复后文件与 Git 原版无 diff，最终测试和构建通过，未计时失败版。
