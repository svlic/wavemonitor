# ADR 0006：使用多级价格梯和固定回撤规则

- **状态**：已接受
- **决策时间**：2026-07-03 至 2026-08-29

## 背景

初版要求每个 Instrument 同时配置一个支撑位、一个阻力位和两个阈值。后续业务需求
要求：只配置一侧价格、按固定回撤派生支撑位，以及为同一策略保存多级支撑阻力。
项目所有者确认，多级价格和固定回撤的引入均源于业务需求。

## 决策

- Instrument 使用 `supports` 和 `resistances` 两个 Decimal 数组，输入顺序不影响
  level 选择；未配置的一侧用空数组表示，不使用 `null`。
- `static` 模式至少配置一侧；所有支撑必须低于所有阻力。
- `fixed_drawdown` 模式由 `high_water - fixed_drawdown` 派生唯一支撑；最多接受一个
  阻力位。
- 有支撑时才要求 near-support 阈值；两侧都存在时才要求 risk/reward 阈值。
- 每次评估先选择当前价格下方最大的支撑和上方最小的阻力，再调用保持标量输入的纯
  规则引擎。
- AlertEvent 保存触发时选中的标量价格对，作为事件快照，而不复制整条价格梯。
- SQLite 将 Decimal 数组保存为 JSON 字符串数组，避免浮点转换。

## 边界语义

历史实现使用严格不等式选择最近价格对。项目所有者确认，“价格恰好等于 level 时忽略
该 level”并不是有意确定的业务规则。因此该边界属于现有实现行为，不应在本 ADR 中
视为不可变需求；修改前需要单独确认并补充决策。

## 结果

### 正面影响

- 一个策略可以表达完整的支撑阻力梯。
- 纯规则函数仍只处理一个价格对，限制了多级改造的影响范围。
- 告警记录保留触发时实际使用的 level，历史解释不依赖当前配置。

### 负面影响和限制

- JSON 数组无法依赖普通 SQL 数值约束验证内部元素。
- 最近价格对会随价格移动，规则状态必须正确处理 pair 切换。
- 固定回撤使用绝对价格额而非百分比；这是业务要求，不是通用回撤模型。
