# ADR 0003：行情源映射归属于监控标的

- **状态**：已接受
- **决策时间**：2026-06-30 至 2026-07-06

## 背景

初版将 `(provider, market_type, symbol)` 设为全局唯一。这会阻止两个不同监控策略
使用同一市场行情。初版更新流程还曾删除并重建全部映射，并在更新过程中提前提交，
失败时可能留下部分配置。

## 决策

- Source Mapping 的身份为
  `(instrument_id, provider, market_type, normalized_symbol)`。
- 不同 Instrument 可以配置相同的供应商、市场类型和 symbol。
- Instrument 创建和完整替换必须在单个数据库事务中完成；唯一键冲突返回 409，
  整体回滚。
- 更新时按身份同步映射，保留仍存在的行，删除已移除的行。
- 删除映射时同步清理其规则状态、告警和遗留行情观测。

在当前领域中，Instrument 因而不仅是证券主数据，也承载一组独立规则和数据源配置，
实际接近一个“监控策略实例”。

## 结果

### 正面影响

- 同一 symbol 可用于多套独立支撑阻力策略。
- 配置替换不会暴露半更新状态。
- 映射生命周期与所属 Instrument 一致。

### 负面影响和限制

- 多个 Instrument 共享同一市场 symbol 时，当前调度器可能重复调用供应商。
- 映射删除依赖应用层显式级联，而不是完全依赖数据库级联约束。

## 后续复审条件

项目所有者确认，当时没有考虑共享行情抓取；如果重复请求成为配额、延迟或成本问题，
可以引入按全局 source identity 聚合的一次抓取、多策略分发机制。该优化不得改变
Instrument 对规则状态和告警生命周期的所有权。

## 历史依据

- `94a7b21`：按身份同步映射并显式级联清理。
- `6c732f4`：使 Instrument 创建具有原子性。
- `94b5660`：唯一键加入 `instrument_id`，并使完整更新整体回滚。
- `934c356`：迁移旧 SQLite 全局唯一约束。
