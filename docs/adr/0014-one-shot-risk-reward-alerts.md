# ADR 0014：盈亏比告警在规则周期内只触发一次

- **状态**：已接受
- **决策时间**：2026-10-04
- **取代范围**：局部取代 ADR 0007 中“所有一般告警在条件失效后 re-arm”的决策

## 背景

盈亏比会随价格在阈值附近波动。沿用条件边沿语义时，价格每次离开阈值再进入都会重新
触发，导致同一组规则配置反复发送含义相同的机会提示。

支撑附近、阻力突破和支撑跌破描述的是新的价格边沿，恢复后再次触发仍有业务价值；
盈亏比则是当前规则周期内“曾达到目标”的机会状态，不需要因价格暂时离开而重新布防。

## 决策

- 每个 Instrument/Source Mapping 的盈亏比告警在同一 `rule_cycle_started_at` 周期内最多
  触发一次。
- 盈亏比失效、价格跌破支撑或越过阻力时，保留 `risk_reward_last_alert_at`。
- 规则字段变化时，沿用现有规则周期机制清除状态；新周期可再次触发一次。
- 其他告警继续采用 ADR 0007 的边沿、分档和 re-arm 语义。

## 结果与权衡

- 价格围绕盈亏比阈值反复进出时不会产生重复通知。
- 服务重启后仍通过持久化状态保持一次性语义。
- 同一规则周期内即使市场先离开、后出现更好的盈亏比，也不会再次提醒；需要再次提醒时
  必须修改规则配置以开始新周期。

## 替代方案与依据

- **继续按条件边沿 re-arm**：会保留当前的重复通知问题，因此不采用。
- **增加 cooldown**：只能降低频率，不能保证只触发一次，因此不采用。
- **所有告警都永久去重**：会丢失新的突破、跌破或再次接近支撑事件，因此只对盈亏比
  应用一次性语义。

依据：项目所有者于 2026-10-04 明确要求盈亏比告警“再入不反复触发，只触发一次”。
