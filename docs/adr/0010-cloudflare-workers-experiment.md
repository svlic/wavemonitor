# ADR 0010：Cloudflare Workers 与 D1 部署实验

- **状态**：已取代
- **采用时间**：2026-09-04
- **从本仓库撤回时间**：2026-09-13

## 背景

项目希望获得免费的托管路径，避免常驻服务器、容器和持久磁盘。为此曾在主仓库实现
第二套 TypeScript 后端，目标是保持与 FastAPI API 基本兼容。

项目所有者确认：采用 Cloudflare 的首要原因是免费托管；从主仓库撤回的决定性原因是
代理限制。该方向没有完全放弃，而是迁移到一个独立代码库继续维护。

## 当时的决策

- 使用 Hono 和 Cloudflare Workers 实现 HTTP API。
- 使用 D1 保存 Instrument、映射、行情观测、规则状态、告警和 delivery。
- 使用两分钟 Cron Trigger 取代常驻进程轮询。
- 使用 Workers Static Assets 同源托管 React SPA。
- 增加 GUI 初始化和设置页面，使 Worker 部署无需预先配置全部 secrets。
- 为从 SQLite 转向 D1 准备数据结构和迁移路径。

## 取代决策

WaveMonitor 主仓库只维护 FastAPI + Docker Compose 运行时。Cloudflare Worker、D1、
Cron、GUI 设置和双后端契约从主线删除；serverless 实现由独立代码库承接，不再要求本
仓库与其保持实现级同步。

## 原因

- **已确认**：Cloudflare 运行时无法使用项目部署所需的行情代理能力，尤其影响受地区
  限制的 Binance 请求。
- **历史事实**：Worker 文档明确记录不支持原 Docker 代理配置，且 Cron 可能延迟。
- **历史推断**：双后端复制 API、规则和持久化逻辑会增加契约同步成本；该因素可从 diff
  观察到，但项目所有者未将其确认为撤回的决定性原因。

## 结果

### 正面影响

- 主仓库重新只有一个后端实现和一套迁移机制。
- Docker 部署可以继续使用 SOCKS5 代理访问全部行情源。
- 独立代码库仍可针对 serverless 环境单独演进。

### 负面影响和限制

- 主仓库不再提供零服务器、免费托管路径。
- 两个代码库之间没有自动契约同步保证，功能可能逐渐分叉。
- serverless 用户无法假设本仓库中的修复会自动出现在独立实现中。

## 历史依据

- `a936461`、`21d69ac`：加入 Worker、D1、Cron 和静态资源部署。
- `0fce022`、`40cda27`：加入 GUI 初始化和设置。
- `6509b0e`：一度将仓库正式描述为双后端架构。
- `50e91aa`：从主线删除整个 Cloudflare 运行时和双后端文档。
- 项目所有者确认：免费托管是采用原因，代理限制是撤回原因，方案转入独立代码库。
