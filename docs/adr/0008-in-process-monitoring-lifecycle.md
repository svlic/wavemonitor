# ADR 0008：在 FastAPI 生命周期内运行监控调度器

- **状态**：已接受
- **决策时间**：2026-06 至 2026-09

## 背景

应用需要持续轮询行情，同时提供配置和诊断 API。初版固定间隔循环直接在异步生命周期
中执行同步 SDK、网络和 SQLite 操作；应用模块导入时还会创建外部客户端。这导致测试
导入副作用、事件循环阻塞风险，以及某次 tick 异常终止整个监控循环的风险。

项目所有者确认，生产短期保证单个应用 worker，不考虑将调度器拆成独立服务。

## 决策

- 调度器作为 FastAPI lifespan 后台任务运行，与 API 进程共同启动和停止。
- Uvicorn 使用 application factory；数据库、供应商目录和行情客户端延迟初始化。
- 完整同步 tick 在线程中执行，并在线程内创建 SQLite Session。
- 每个 tick 捕获顶层异常、更新 readiness，并在等待下一周期后继续运行。
- 一个 source 失败只记录该 source 错误，不阻止其他 source。
- 使用 `WakingTicker`：Instrument 创建、修改或启停后立即请求一次 tick，而不等待完整
  轮询间隔。
- 轮询间隔由环境变量配置；测试可显式关闭默认调度器或注入假生命周期。

## 结果

### 正面影响

- 部署仍只有一个后端进程和一个数据卷，符合单实例产品边界。
- 同步第三方 SDK 不阻塞 FastAPI 事件循环。
- 配置变化能快速反映到行情状态。
- 生命周期和依赖可在测试中替换。

### 负面影响和限制

- 启动多个 Uvicorn worker 会启动多个调度器并重复轮询、告警。
- API 可用性和监控任务仍共享进程故障域。
- 长时间 tick 会占用线程，并推迟下一轮开始时间。

## 后续复审条件

只有在需要多 API worker、高可用、任务水平扩展或独立故障隔离时，才将调度器拆为独立
进程或服务，并同时设计租约、分布式锁或消息队列。短期不进行该拆分。
