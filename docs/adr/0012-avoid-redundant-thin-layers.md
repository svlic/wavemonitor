# ADR 0012：避免没有独立职责的薄抽象层

- **状态**：已接受
- **决策时间**：2026-09

## 背景

快速开发过程中产生了多个仅承载类型、单条查询、单一转发函数或一个调用方的模块，
前端也出现了只包装 `setInterval` 的 hook、只传递加载结果的 bundle helper，以及后来
不再必要的全局 revision store。

Git 提交将后续清理描述为“remove redundant layers/modules found by ablation”。没有证据
表明所有小模块都应删除；历史变化支持的原则是：抽象必须拥有独立职责，而不是仅增加
跳转层级。

## 决策

- 只有在满足至少一个条件时保留独立模块或 helper：
  - 被多个调用方复用；
  - 隔离外部副作用或基础设施边界；
  - 承载可独立说明和测试的领域职责；
  - 明显降低调用方复杂度。
- 仅包含类型别名、单一查询或参数转发，且只有一个调用方的代码优先回收到实际所有者。
- 不为了减少文件数而合并真正的边界；Telegram delivery、API 入站 Zod 校验、行情适配器
  和纯规则计算仍保持独立。
- 重构本 ADR 所涉及的边界时应保持行为不变，并依赖现有回归测试验证。

## 结果

### 正面影响

- 减少跨文件追踪和一次性抽象的维护成本。
- 模块名称更接近实际所有权边界。
- 避免为简单 React 页面状态引入自建全局状态机制。

### 负面影响和限制

- 所有者模块可能逐渐变大，需要持续判断是否已经形成新的独立职责。
- “只有一个调用方”本身不是充分的内联理由；过度应用会损害测试和边界清晰度。
- 该原则来自历史重构归纳，不证明被删除的每一层最初都没有价值。
