# ADR 0001：采用单实例全栈与轮询架构

- **状态**：已接受
- **决策时间**：2026-06-30
- **重建时间**：2026-09

## 背景

项目从零开始构建，目标是监控股票和衍生品价格、执行支撑阻力规则并通过
Telegram 告警。项目所有者确认，产品面向个人或小团队的单实例部署；当时没有
评估 PostgreSQL 等数据库，也没有额外考虑 API 配额或基础设施成本。

初始规划直接记录了以下约束：不交易、不保存交易所账户信息、不建立多租户账户
体系、不以 WebSocket 作为首个行情接入方式，并且规则计算不得使用浮点数。

## 决策

采用以下整体架构：

- Python 3.11+、FastAPI、SQLModel 和 SQLite 构成后端。
- React、TypeScript 和 Vite 构成管理前端。
- 前后端分别构建容器，由 Docker Compose 部署；Nginx 同源转发 `/api`。
- 后端在单一常驻进程内按固定周期轮询行情，而不是维持 WebSocket 数据流。
- 价格、阈值和规则计算使用 `Decimal` 或等价的十进制定点表示。
- Telegram 凭据只由后端从环境变量读取。

## 结果

### 正面影响

- 本地开发、单机部署和数据备份路径简单。
- 轮询流程易于使用假适配器和固定时间进行确定性测试。
- 前后端技术边界清晰，前端不接触 Telegram 等服务端密钥。

### 负面影响和限制

- SQLite、进程内调度器和本地状态使多实例横向扩展不属于当前支持范围。
- 轮询存在固定延迟，不能提供实时行情语义。
- 如果未来转为多用户或高可用部署，需要重新评估数据库、调度归属和状态协调。

## 已考虑的替代方案

- **WebSocket-first 行情接入**：初始规划明确排除，优先确定性和可测试性。
- **PostgreSQL 或其他数据库**：当时未评估。
- **其他前后端组合**：没有可确认的评估记录。
