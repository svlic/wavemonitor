# ADR 0004：为公网部署提供可选共享密码认证

- **状态**：待复审
- **决策时间**：2026-07-01

## 背景

初始 MVP 明确不建立用户、角色或多租户系统。项目后来需要直接部署到公网，因此仍需
提供最低限度的访问控制。项目所有者确认，未来可能更多依赖反向代理服务器本身的
认证能力。

## 决策

- 通过 `WAVEMONITOR_WEB_PASSWORD` 可选启用一个全站共享密码。
- 认证成功后签发 7 天有效的 `HttpOnly`、`SameSite=Lax` Cookie。
- Cookie 值使用 HMAC 签名，不在 Cookie 中保存密码。
- 优先使用显式配置的 `WAVEMONITOR_SESSION_SECRET`；未配置时生成随机密钥并保存到
  SQLite 文件旁的持久卷。
- 启用认证时保护 `/api/*`，认证端点除外；`/health` 始终公开。
- 未配置密码时不启用认证，以保持本地和受信网络部署兼容。

## 结果

### 正面影响

- 无需账户表、密码重置或权限模型即可降低直接公网暴露风险。
- 自动持久化签名密钥，容器重启后会话仍可验证。
- Telegram 和其他服务密钥仍不经过浏览器。

### 负面影响和限制

- 所有操作者共享同一身份，无法审计个人操作或分配权限。
- 应用自身不终止 TLS；公网安全依赖反向代理正确配置 HTTPS。
- 自动生成的本地密钥不适合多个应用实例共享。
- 应用认证与反向代理认证可能形成重复登录体验。

## 后续方向

当部署环境稳定依赖反向代理认证时，应复审是否关闭或移除应用内密码，而不是继续扩展
为完整账户体系。除非产品边界改变，本 ADR 不授权新增多用户权限系统。
